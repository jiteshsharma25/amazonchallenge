# Business Entity Resolution Pipeline

This repository contains a complete, production-ready Machine Learning pipeline for the Business Entity Resolution Challenge. The system is designed to map business records from a clean, deduplicated reference source (Source 1) to noisy fragments in two independent data sources (Source 2 and Source 3).

The pipeline prioritizes **precision** and **computational efficiency**, utilizing a multi-stage blocking architecture combined with a calibrated LightGBM model optimized specifically for the entity-level macro $F_{0.5}$ metric.

---

## 🏗️ System Architecture & Code Pipeline

The solution avoids computationally impossible Cartesian products (comparing every record to every other record) by splitting the problem into two distinct phases: **High-Recall Blocking** and **High-Precision Classification**.

### 1. Data Normalization (`src/normalization.py`)

Before any matching occurs, all text fields are standardized.

* **Business Names:** Accents are removed, punctuation is normalized, and legal suffixes (e.g., "pvt ltd" $\rightarrow$ "private limited") are mapped. We generate multiple representations: raw, alphanumeric, sorted-tokens, and suffix-stripped.
* **Addresses:** Abbreviations are expanded (e.g., "St" $\rightarrow$ "street"), and highly discriminative numerical tokens (house numbers, PIN codes) are extracted into separate arrays.
* **Countries:** Handled as an open-set string label to accommodate unseen countries in the test set (e.g., France).



### 2. Multi-Stage Blocking (`src/blocking.py`)

Generates a highly restricted pool of plausible candidate pairs to feed to the ML model.

* **Exact Name Blocking:** Captures trivial matches instantly.
* **Postal Code Blocking:** Connects entities sharing rare local postal identifiers.
* **TF-IDF Nearest Neighbors:** Converts business names into character n-gram vectors (2-4 chars) and retrieves the top 15 mathematically closest candidates using sparse cosine similarity. This captures typos, missing words, and transliterations.

### 3. Pair Feature Engineering (`src/features.py` & `src/dataset_builder.py`)

For every Source 1 $\leftrightarrow$ Candidate pair generated by the blocker, we compute a dense numerical feature vector:

* **String Distances:** Levenshtein ratio, Jaro-Winkler, and RapidFuzz token-sort/set ratios.
* **Address Specifics:** Exact numeric token overlap (ensuring 102 Main St does not match 104 Main St) and postal code agreement.
* **Structural Indicators:** Length differences, missing value flags, and source-origin indicators.

### 4. Machine Learning Model (`src/models.py`)

A LightGBM (Gradient Boosting Decision Tree) binary classifier trained on the feature vectors.

* **Hard Negative Mining:** By training *only* on the difficult pairs generated by the blocking stage (rather than random pairs), the model learns to aggressively distinguish between highly similar but distinct businesses.

### 5. Threshold Optimization & Singletons (`src/thresholding.py` & `src/evaluation.py`)

Because the evaluation metric is macro $F_{0.5}$, precision is weighted twice as heavily as recall.

* The system does not use a default 0.5 probability cutoff. Instead, `thresholding.py` grid-searches the validation predictions to find the exact decimal threshold that maximizes the F0.5 score.
* Source 1 entities failing to meet this strict threshold are predicted as "Singletons" (empty matches), avoiding massive false-positive penalties.

## 🚀 How to Run the Pipeline (Start to End)

### Step 1: Environment Setup

Ensure you are using Python 3.10 or higher. It is highly recommended to run this inside an isolated virtual environment.

Open your terminal (or PowerShell) in the root `business-entity-resolution/` directory:

```powershell
# Create the virtual environment
python -m venv venv

# Activate it (Windows PowerShell)
venv\Scripts\Activate.ps1

# Upgrade pip and install dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt

```

### Step 2: Model Training & Validation

Execute the training script. This script handles the train/validation split (ensuring no data leakage by splitting strictly by Source 1 IDs), normalizes text, runs blocking, extracts features, trains LightGBM, and searches for the optimal F0.5 threshold.

```powershell
python train.py

```

**Expected Output:**

* Logs detailing candidate generation sizes.
* LightGBM training progress.
* Final Validation Macro F0.5 score and the Optimal Probability Threshold.
* Artifacts saved to the `models/` directory (`final_model.joblib` and `threshold.json`).

### Step 3: Inference on Unseen Test Data

Once the model is trained, execute the prediction pipeline. This applies your saved model, normalization rules, and optimized threshold to the test dataset.

```powershell
python predict.py

```

**Expected Output:**

* `output/matching_results.tsv`: The final precision-filtered entity matches.


* `output/candidate_pairs.tsv`: The raw candidate pairs evaluated by the model.



### Step 4: Validate the Output Format

The challenge enforces strict formatting rules (tab separators, no duplicate IDs, correct headers, empty strings for singletons). Run the validation utility before submitting:

```powershell
python utils/validate_submission.py --matching output/matching_results.tsv --candidate output/candidate_pairs.tsv --test-dir dataset/test

```

*You must see `PASS (exit 0)` before uploading.*

### Step 5: Packaging for Submission

Zip the required files to upload to the challenge portal.

```powershell
Compress-Archive -Path output\*, src\*, train.py, predict.py, README.md -DestinationPath final_submission.zip

```

## ⚙️ Configuration & Experimentation

All hyperparameters are centralized in `configs/config.yaml`. To improve the model's score iteratively, you can modify these without changing the Python code:

* **`top_k_neighbors`:** Increase this (e.g., from 15 to 30) to generate more candidates and improve recall, at the cost of higher RAM usage and longer feature-extraction times.
* **`tfidf_ngram_range`:** Adjust character n-grams (default is `[2, 4]`).
* **LightGBM Params:** Tune `learning_rate`, `num_leaves`, and `max_depth` to optimize classification accuracy on the feature vectors.
